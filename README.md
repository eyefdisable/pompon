# Помпон — шаблон приложения для выездной химчистки мягкой мебели

Клиент открывает ссылку, выбирает мебель на вращаемой 3D-модели, сразу видит примерную стоимость и отправляет заявку с адресом и фото. Владелец видит заявку в защищённом кабинете, связывается с клиентом, задаёт итоговую цену и время. Клиент видит обновление по приватной ссылке.

Стек: Node.js 22 + TypeScript, React 19 (серверный рендер публичных страниц и SPA), PostgreSQL 16, собственный WebGL2-движок для 3D, PWA.

## Быстрый старт

```bash
npm install                 # нужен доступ к npm
cp .env.example .env        # заполните DATABASE_URL, APP_SECRET, OWNER_INITIAL_PASSWORD
npm run build               # модели, клиент, сервер → dist/
npm run db:migrate          # схема БД (идемпотентно)
npm start                   # http://localhost:3000, кабинет: /kabinet
```

Локальная база, если PostgreSQL ещё нет: `docker run -d -p 5432:5432 -e POSTGRES_PASSWORD=dev -e POSTGRES_DB=pompon postgres:16`.

Команды:

| Команда | Что делает |
|---|---|
| `npm run models` | пересобрать GLB-модели из `scripts/build-models.ts` (с проверкой, что руки не заходят в корпус) |
| `npm run build` | собрать всё в `dist/` |
| `npm run typecheck` | проверка типов (с `@types/react`) |
| `npm test` | тесты формулы и валидации |
| `npm run e2e` | сквозная проверка в браузере (Python + Playwright, сервер должен быть запущен, `OWNER_PASSWORD` = пароль владельца) |

## Публикация

Подходит любой хостинг, где работает Node 22 и есть PostgreSQL: VPS (systemd или pm2 + nginx), Render, Railway, Fly.io и подобные.
1. Создайте базу PostgreSQL 16+ и задайте `DATABASE_URL` (для облачных БД — с `?sslmode=require`).
2. Задайте `APP_SECRET` (случайные 32+ символа), `OWNER_INITIAL_PASSWORD`, `PUBLIC_ORIGIN=https://ваш-домен`, а за прокси — `TRUST_PROXY=1`.
3. Сборка: `npm ci && npm run build`. Перед запуском: `npm run db:migrate`. Запуск: `npm start`. Проверка: `GET /healthz`.
4. Нужен HTTPS (без него не работают установка PWA и Secure-cookie кабинета).

Все данные (заявки, фото, сессии, лимиты запросов) хранятся в PostgreSQL. Локальных файлов с данными нет, поэтому несколько экземпляров сервера можно запускать за балансировщиком.

## Как устроено

```
src/shared/      прайс по умолчанию, формула, валидация, реплики, постер — общее для сервера и браузера
src/server/      HTTP-сервер, API, SSR-страницы, клиент PostgreSQL (протокол v3, SCRAM, TLS)
src/client/      витрина и оформление (app.tsx), кабинет (admin.tsx), 3D (three/), стили, сервис-воркер
scripts/         сборка, генерация моделей и иконок, миграции
db/schema.sql    схема базы
models/          готовые GLB
tests/           юнит-тесты (формула) и e2e (браузер)
docs/            адаптация, ограничения, скриншоты
```

### Формула расчёта (одна для браузера и сервера)
1. Базовая цена варианта.
2. Матрас со второй стороной: × (1 + % второй стороны).
3. Сильные загрязнения: × (1 + % загрязнений).
4. Цена позиции округляется до шага (10 ₴, половина вверх) и умножается на количество.
5. Сумма чистки. Если в заказе нет «Другого» — не меньше минимального заказа.
6. Выезд за город — фиксированная доплата после минимума, отдельной строкой.

«Другое» стоит «по фото». В сумму такие позиции не входят и бесплатными не показываются. Минимум к известной части смешанного заказа не применяется: итог чистки станет ясен после оценки владельцем.

Сервер пересчитывает заявку сам и игнорирует сумму из браузера. В заявке сохраняется снимок прайса и расчёта, поэтому новый прайс не меняет старые договорённости.

### Безопасность
- **Кабинет:** пароль хранится как scrypt-хэш. Сессия — HttpOnly-cookie с SameSite=Strict, в базе лежит только хэш токена, срок 14 дней. Смена пароля закрывает все прежние сеансы.
- **Изменяющие запросы:** принимаются только со своего Origin. Лимиты запросов хранятся в БД: вход, отправка заявки, загрузка фото, просмотр заявки.
- **Приватная ссылка клиента:** HMAC(APP_SECRET, ключ идемпотентности), в базе — только её sha256. Номер заявки (`П-00001`) доступа не даёт.
- **Повтор после сбоя сети** с тем же ключом возвращает ту же заявку и не создаёт дубль.
- **Фото:** сервер проверяет настоящий формат по сигнатуре JPEG, PNG или WebP, ограничивает размер (10 МБ, 40 Мп), пережимает в WebP до 1600 px и удаляет EXIF и геометку. Хранятся в БД и отдаются только владельцу после входа. Публичный API фото, телефон и заметку владельца не отдаёт.
- **Заголовки:** строгая CSP (без инлайн-скриптов), nosniff, запрет встраивания во фреймы.

### 3D
Собственный небольшой WebGL2-движок (`src/client/three/engine.ts`): загрузка GLB, планарная тень и контактное пятно, вращение пальцем и мышью, на клавиатуре — стрелки и «0». Наклон камеры ограничен, есть сброс ракурса. Рендер идёт только при изменениях, DPR ограничен 1,75, сцена ставится на паузу вне экрана. Все модели загружаются заранее: смена категории плавная, а при быстрых переключениях побеждает последнее. Без WebGL показывается постер, при ошибке загрузки — кнопка «Повторить». При `prefers-reduced-motion` анимации отключаются.

Мини-игра: пятна лежат в UV-маске 512×512. Курсор или палец даёт луч, он пересекается с треугольниками, по UV стирается маска. Пятна закрываются геометрией и вращаются вместе с предметом, режимы «Чистить» и «Вращать» разделены.
